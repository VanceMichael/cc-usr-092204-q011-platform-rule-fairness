# 平台规则公平变更

本项目服务于记录平台算法、流量和价格规则的发布与影响。仓库保存领域资料、交换契约和可运行的服务入口，便于参与方在同一语义下协作。

## 领域事实

- 监管将加强平台数据、算法、流量和规则治理
- 平台企业承担守门人责任
- 整治目标包括低价内耗与不正当竞争

## 目录说明

- `contracts/` 保存交换数据的结构约定（发布包、变更事件）。
- `fixtures/` 提供去标识的领域样例（发布包、竞争指标）。
- `src/catalog.py` 提供领域资料读取。
- `src/fairchange/` 是公平变更后台核心：
  - `model.py` 发布包模型与冻结哈希；
  - `store.py` 只增不改的事件日志；
  - `service.py` 发布、会签、灰度归属、止损回滚、豁免与反查；
  - `analysis.py` 竞争影响预警（集中降权、被迫跟价、退出困难）；
  - `disclosure.py` 按角色最小披露与审查复算。
- `src/server.py` 提供健康检查与 JSON API 入口。
- `tests/` 核对领域资料、生命周期、权限、预警与追溯。

## 核心机制

- **发布包冻结**：算法版本、适用商家、流量入口、补贴条件、价格约束、通知与申诉冻结为不可变内容，以内容哈希标识。
- **灰度曝光归属**：灰度期间每次曝光都记录当时生效的发布包、内容哈希与算法版本。
- **历史不可抹去**：紧急止损、回滚、豁免均以新事件追加，事件日志没有修改与删除入口。
- **可解释预警**：规则组合造成异常集中降权、被迫跟价或退出困难时，产出带证据与解释文本的预警。
- **最小披露**：商家机密与平台模型细节按角色最小范围披露；审查人员可复算影响，但不能修改生产规则。
- **唯一正式版本**：多团队可并行会签，正式版本全平台唯一，取代必须显式声明。
- **上线前检查**：发布前列出受影响群体与未完成通知，未完成则拦截（紧急发布需记录理由）。
- **事后反查**：上线后可从投诉或竞争指标反查具体规则、审批依据与发布事件。

## 本地检查

运行 `python3 -m unittest discover -s tests -v` 可以检查当前资料与服务入口。

启动服务：`python3 -m src.server`，默认监听 `127.0.0.1:8000`。写操作需请求头 `X-Actor-Role: operator`，审批需 `approver`，完整事件日志仅 `auditor` 可见；缺省角色为只读的 `reviewer`。
